# 银行收付款开发顺序清单

版本：V0.1 讨论稿｜日期：2026-11-16｜范围：收款 + 付款。

返回：[需求图解](需求图解.md) · [关键接口契约](关键接口契约.md)。

这是建议开发依赖顺序，不代表排期或已批准实现。没有支付工程和银行协议依据，全部任务保持未勾选；文档已生成不等于开发、联调或资金验收完成。前置 Q 问题在需求图解统一维护，仅阻塞受影响任务。

## 阶段一：确认业务边界与可复用实现

- [ ] **T01 确认银行、产品及准入能力**。前置：无。完成条件：Q01／Q07 有银行正式资料，逐项确认发起、查单、通知、账单、状态语义和沙箱，不支持项有可执行替代方案。依据：图 01、02、08；K03—K05、K08。
- [ ] **T02 确认收付业务与资金规则**。前置：无，可与 T01 并行讨论。完成条件：Q02—Q08 明确账户主体、方式、金额费用、分次重试、权限／审批、逆向范围、到账与对账口径；对依赖银行的信息待 T01 后交叉核定。依据：R01—R09。
- [ ] **T03 扫描支付工程与现有能力**。前置：获得 Q09 对应仓库及说明。完成条件：先读取 AGENTS.md，定位真实订单／财务、权限、银行适配、调度、通知及审计实现，记录复用／调整／新增边界和真实数据归属。依据：图 10；K01—K09。
- [ ] **T04 形成可实施的契约和验收基线**。前置：T01、T02、T03。完成条件：冻结本期范围与规则，补真实银行和工程签名、状态映射、失败／查无记录语义及兼容；A01—A12 按确认能力细化，Q10 的规模和处理责任有结论。依据：需求图解附录；K01—K09。

## 阶段二：共同控制先行

- [ ] **T05 落实数据模型、访问路径与本地一致性**。前置：T04。完成条件：真实结构涵盖收付单、不可变快照、请求与证据、防重和业务生效依据；同键异参及同业务并发受控；列出索引候选并以执行计划检查关键读写的扫描量、锁与 IO。SQL 最多关联两表，代码聚合同时检查查询次数。依据：图 03、04、07；R02、R03、R06、R07。
- [ ] **T06 实现银行适配与安全配置**。前置：T04。完成条件：按真实协议完成发起、可行查证、状态映射、认证／签验及受控密钥配置；沙箱记录能关联原请求；不支持回调或重放时有明确处理边界。依据：K03—K05；R04、R05、R10。
- [ ] **T07 实现统一结果归并及业务生效保障**。前置：T05、T06。完成条件：重复与乱序不重复生效或倒退，冲突进核验；本地提交不跨银行；跨系统时原结果可恢复投递且消费防重，同库则共同提交。依据：图 07、08；K04—K06；A06、A07、A09。

T05 与 T06 可在 T04 后分工并行；这里说明任务依赖，不指定必须拆分服务或新增中间件。

## 阶段三：分别完成收款、付款正向链路

- [ ] **T08 完成收款主链及客户必要交互**。前置：T07。完成条件：按 Q02 确认方式贯通应收关联、K01 发起、客户操作和结果查询；客户端不能更改权威金额；A01、A03 在确认范围内有验证记录。若选择转账认领，先补该模式独立流程与契约再实现。依据：图 01、03、05；K01、K03、K07。
- [ ] **T09 完成付款主链与并发待付约束**。前置：T07。完成条件：K02 账户快照和权限正确，同待付义务不同请求不并发超额；受理不冒充到账，未知不自动解除约束；明确失败才按规则处理在途。依据：图 02、04、06；K02、K03、K07；A02—A05、A11。
- [ ] **T10 完成超时、宕机与投递恢复**。前置：T08、T09。完成条件：A05、A08、A09 覆盖关键中断窗口，恢复沿原请求查证；银行不保证安全重放时不自动重发；次数／时限耗尽转有责任人的核验，不能直接改失败。依据：图 05—07；K04、K06；R05、R11。
- [ ] **T11 完成收付查询与操作反馈**。前置：T08、T09。完成条件：有权限用户能区分处理中、待确认、成功和明确失败；显示可信时间、脱敏账户及对账结论；查询故障与零金额、无记录分别处理。依据：图 08；K07；R01、R08、R11。

T08 与 T09 可在共同控制稳定后并行；T10 与 T11 的分工需结合实际共享文件和团队安排，不预估无依据工期。

## 阶段四：对账、验收与生产交接

- [ ] **T12 完成银行证据获取、对账与差异闭环**。前置：T10、T11。完成条件：按 Q08 实际来源校验账单完整性、重复和更正版；A12 可复现；K09 仅提交有证据且有权限的核验，不自动触发资金逆向动作或手改支付成功。依据：图 09；K08、K09；R08、R09。
- [ ] **T13 执行关键资金风险验证与必要联调**。前置：T12。完成条件：A01—A12 中适用项都有可核查结果；高风险重复、并发、未知结果、伪造／越权和回调落库失败有针对性验证；不支持的条件能力说明替代验证，不伪称通过。不为文档或低风险改动自动全量编译。依据：需求图解附录 C；R01—R11。
- [ ] **T14 确认生产参数、观察与异常交接**。前置：T13。完成条件：Q10 的规模／SLA、查询与重试限流、未明与差异处理时限、证书轮换、留存和责任落实；依据真实数据检查关键 SQL 与 IO，留上线与停发方案。回退只停止新发起并继续查证在途，不能撤销已发生的银行资金事实。依据：R05、R09—R11；K03—K09。

## 范围变更处理

Q06 若确认退款、撤销、分账或批量属于本期，先新增对应业务图、状态、契约和验收，再追加稳定任务编号。Q02 若选转账认领或其他不同收款方式，也先补独立链路。已有任务编号、勾选与备注后续应保留；规则变化时仅将受影响项标记待复核。
