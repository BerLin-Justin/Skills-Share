# 图示内容与排版规范

## 先定问题 再定图

每张图先写一句内部目的，例如“JSD 放行为什么不等于挂账”，据此选择节点和连线。先把确定对象、规则、状态和冲突统一成一份内部模型，再从不同视角作图，不独立写四套规则。

| 图种 | 图中必须讲清 | 常见不合格 |
| --- | --- | --- |
| 业务流程／泳道 | 角色、触发、条件、动作、结果、拒绝／例外及继续路径 | 只有正常箭头；角色不明；失败后无结果 |
| 数据流转 | 生产方、具体输入、处理读写、实体／关系、输出、关联键和权威 | 泛泛前后端数据库；ER图无流向；申请与事实混算 |
| 时序 | 参与者、时间向下、消息方向、同步／异步、提交、返回、异常和重复 | 流程冒充；只有调用没有结果；事务跨外部系统 |
| 技术架构 | 系统边界、职责分层、调用、数据归属、改动及证据状态 | 无来源技术栈；所有组件都称现有；模块等于微服务 |

金额／票据场景标出哪一份金额、何时有效；库存／额度标预占、转消耗、释放；快照标保存时点和当前状态。没有对应场景不生搬这些内容。

## 内容完整而不堆满

- 判断写具体，例如“本次有效分配首次足额且开关开”，不用“判断是否正确”。
- 失败写清保留什么、撤销什么、用户下一步；重试回到受控入口，不循环创造新事实。
- 分清提交成功、审批成功、实际生效和资金发生，不因名称相近合并。
- 一图一个层级。全景展示主干与子图引用，详细图承载例外、金额、并发和补偿。
- 概览通常约 6—12 节点，详细图约 10—18 节点；拥挤则拆图，不缩字号或删关键边界。
- 数据箭头写“读取可用额度”“写入逐单分配”等动宾标签；实体只写必要键及单位，不堆全字段。
- 多对多画关联明细和归属额，不能用无标签连线暗示全额自动覆盖。
- 未定接待确认节点或清晰候选分支，不把建议画成已确认实线主链。
- 时序单图通常聚焦一个提交／审批／恢复阶段；主要交互超过约 12 条且需要多个分支时优先拆分。不能把完整业务生命周期压成一张很长的生命线图。

## 统一视觉语言

白底、深字、适度留白；业务／界面蓝，处理绿，数据橙，风险红，外部灰。同一对象跨图保持颜色和名称；新增／修改／复用加文字角标，不单靠颜色。

主干优先左到右，判断多的细图可上到下。架构分层，数据按生产→处理／存储→消费，时序保持稳定参与者列、消息编号与从上到下的顺序。

连线不穿节点，边标签不盖交叉点；节点通常不超 3—4 行，长条件分配到判断边或图注，不能拆坏字段名和金额。标题直说主题，保留边距和紧凑图例；虚线用于异步或候选时须有文字区分，不能一图同义混用。

## 尺寸和可读性

按 Markdown 约 1000—1200 像素内容宽度检查。参考节点字号 16—18、边标签 13—15 像素，注意 SVG pt 与 px 换算，最终以实际展示判断。优先保留 SVG，正文可用约 1800—2400 像素宽 PNG。

高清不能解决密图：缩回文档宽度后字仍小、连线挤或高度需反复滚动就拆图。小图不放成巨大空白，复杂图不压字号；一张总览配数张细图优于几千像素的巨图。

## 短注与质量门槛

每图短注回答：做什么、为什么、关键边界，通常三句话以内。图已写“审批只出未开始单”，文字解释“防止批准额度冒充挂账凭据”，不用再念一遍箭头。

实际查看全部渲染图：中文、符号齐全；框不裁字；边不盖字；角色与方向清楚；分支有结果；范围外不装作正常能力；正常宽度可读。

跨图核对：流程中的关键事实在数据图有归属，关键交互在时序有参与者，时序模块能在架构找到，状态、金额、键和待确认标记一致。不能以“能解析”“有PNG”“四个标题齐了”代替内容和视觉验收。旧截图不抵扣四类图覆盖。
