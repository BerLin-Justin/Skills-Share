返回：[需求图解](需求图解.md) · [开发顺序清单](开发顺序清单.md)。

## 二、共用约定

- 身份由可信会话或服务认证提供；每次核对业务单、银行配置与账户数据范围。银行认证方式及报文保护以 Q01 为准。（R01、R10）
- 业务请求标识、本地收付单标识、银行请求标识、银行交易标识各有职责，不能混用。防重范围至少区分主体与收付方向；同键异参拒绝。具体命名与协议位置待定。（R03）
- 金额带币种，申请、银行交易、费用及实收实扣分别表达；缺失为未知而非零。时间保留业务含义及明确时区，银行发生时间与本地接收时间不混淆。（R02、R04）
- 业务拒绝、认证失败、依赖故障、已受理、结果未明分别返回可理解语义。网络超时不等于银行失败；调用方保留原业务关联，不能自动换新单重试。（R04—R06）
- 本地事务不涵盖银行执行。外部请求发出前留存恢复所需关联；银行重放安全性未经核实时，采用查证与人工核验，不假设对方支持幂等。（R05）
- 本文不创建实际字段与数据库结构。Q09 明确后核对既有协议和旧调用方；新增字段的默认、空值和历史兼容须再补充。

## 三、逐调用要求

### K01 创建／取得收款意图

| 项目 | 需求级约定 |
| --- | --- |
| 输入含义 | 业务应收标识、本次请求标识、期望收款意图；允许前端选择的支付方式取决于 Q02。账户与最终金额由服务端业务规则校验，不能照抄前端。 |
| 返回含义 | 原／新收款单关联、当前状态、申请金额和币种；若银行产品需要客户继续操作，返回受控操作信息，具体载体待定。 |
| 校验与拒绝 | 无权操作、业务不存在、应收不可支付、账户不匹配、金额非法、同键异参、并发超应收范围拒绝；部分／多次收款规则待 Q04。 |
| 重复与后续 | 同标识同内容取得原结果；未知或处理中展示进度。只有在确认旧请求结论且满足 Q04 后才能新发起，不自动重扣。 |
| 依据／阻塞 | R01—R05；A01、A03、A05、A08；Q01—Q04、Q07、Q09。 |

### K02 创建／取得付款意图

| 项目 | 需求级约定 |
| --- | --- |
| 输入含义 | 待付业务、本次请求标识、付款用途、经授权选择的企业出款账户与收款人资料、申请金额和币种；按已确认规则形成不可变快照。 |
| 返回含义 | 原／新付款单、当前进度、快照摘要；受理和待确认需与成功分别展示，不承诺到账时间。 |
| 校验与拒绝 | 越权、账户或收款人不合规则、金额不合法、已付／在途超范围、同键异参拒绝；是否审批、额度和冻结待 Q05。 |
| 并发与后续 | 同键防重之外，还核验同一待付义务的不同请求；未知期间不能因新请求标识释放并重复付款。银行明确失败后的在途解除依 Q05。 |
| 依据／阻塞 | R01—R03、R05、R07；A02—A05、A08、A11；Q01、Q03—Q05、Q07、Q09。 |

### K03 提交银行资金请求

| 项目 | 需求级约定 |
| --- | --- |
| 输入含义 | 收付方向、稳定银行请求关联、本地单快照、账户与交易信息；收款的客户授权凭据仅在产品确需且合规授权时提供。 |
| 返回含义 | 银行关联标识、原始响应语义及可核验的处理阶段；成功终态、明确失败、已受理、结果未明分别处理。不是所有响应都包含银行交易标识。 |
| 本地提交 | 先保存单据、请求快照及可恢复发送意图，再对外调用。恢复时能识别是否可能已发送；无法证明未发送时先查证，不直接再发。 |
| 失败与重放 | 拒绝／认证问题停止盲重试；通信失败保持原请求。仅银行明确保证幂等范围、窗口及同参要求后，才按其规则重放；绝不声称本地唯一约束能保证外部只扣一次。 |
| 依据／阻塞 | R02—R05、R10；A03、A05、A08；Q01—Q05、Q07。 |

### K04 查证原交易结果

| 项目 | 需求级约定 |
| --- | --- |
| 输入含义 | 按协议可查询的原请求／银行交易关联及所属账户上下文；没有银行交易标识时是否能按客户端标识查证须先核实。 |
| 返回含义 | 原始处理状态、可用交易信息、银行状态时间；明确“查无记录”“查询暂不可用”“处理中”“最终失败”“最终成功”。未支持的字段留未知。 |
| 结果使用 | 核验交易、账户、方向、金额、币种后进入统一归并；只读调用不另造资金幂等键。若不同证据冲突，保留证据并转核验。 |
| 调用方处理 | 频率、窗口和限流按 Q01／Q10；查无记录不自动等于安全重发。查证超期转指定人工责任，不凭次数耗尽改失败。 |
| 依据／阻塞 | R04—R06、R11；A05—A08；Q01、Q04、Q07、Q10。 |

### K05 接收银行结果通知（条件能力）

| 项目 | 需求级约定 |
| --- | --- |
| 启用条件 | 仅在 Q01 确认银行支持并明确通知认证、重试、确认协议后启用；不支持时以可行的查证渠道保障闭环。 |
| 输入含义 | 银行结果证据、交易／请求关联、状态和时间及其真实性校验材料；银行事件唯一标识若有则保留。 |
| 核验与归并 | 先验真、验归属和防重放，再核交易与金额；持久化后按协议确认。无事件标识时需明确业务去重依据，不能简单以到达时间去重。 |
| 拒绝／恢复 | 伪造或不归属证据不生效；合法但不匹配进入差异。重复通知不重复业务影响；持久化失败不能确认已处理；具体响应待银行协议。 |
| 依据／阻塞 | R01、R04、R06、R10；A06、A07、A10；Q01、Q07、Q10。 |

### K06 投递业务结果（跨系统条件能力）

| 项目 | 需求级约定 |
| --- | --- |
| 启用条件 | 收付结果与应收／待付业务不在同一可原子提交边界时使用；同库可直接共同提交，具体按 Q09。 |
| 输入含义 | 稳定结果标识、主体、业务关联、收付方向、本地单关联、已核验状态与业务金额；不携带不必要的敏感银行报文。 |
| 消费与确认 | 业务侧校验服务身份与归属，按结果标识防重后更新业务；重复投递返回已有应用结论。业务确认与其业务更新需具备一致性。 |
| 异常处理 | 生产侧持久化待投递记录；超时保持原结果重试。业务已生效但确认丢失时不重复应用。超过处理窗口转可见待办，不能丢弃结果。 |
| 依据／阻塞 | R03、R06、R11；A09；Q09、Q10。 |

### K07 查询收付款记录与详情

| 项目 | 需求级约定 |
| --- | --- |
| 输入与范围 | 有权限的业务／本地单标识，列表按业务归属、方向、状态、账户与时间范围筛选；主体来自可信身份。 |
| 返回含义 | 申请额与币种、当前支付进度、最后可信更新时间、失败／待确认说明、独立对账结论；银行证据与账户内容按角色脱敏。 |
| 空值与故障 | 未找到、无权访问与暂时查询失败按工程安全规范区分；不把获取失败返回为零金额或支付失败。是否隐藏资源存在性由实际权限规范确定。 |
| 分页与性能 | 使用稳定排序及唯一标识作为并列次序，分页边界待工程确定。限制查询范围和批量大小，实际索引、扫描量、IO 与查询次数经执行计划验证；最多两表关联。 |
| 依据／阻塞 | R01、R08—R11；A10；Q08—Q10。 |

### K08 获取银行证据并执行对账

| 项目 | 需求级约定 |
| --- | --- |
| 触发与输入 | 按确认账期触发，输入银行配置、账户、方向、币种、账期和来源批次；接口／文件／导入方式待 Q08。 |
| 返回与进度 | 区分获取失败、未就绪、已获取为空、已完整获取；保留源批次、版本与完整性信息（若有），提供核对进度和差异结果。 |
| 防重与重跑 | 同来源批次重复取得不重复制造差异或业务影响；更正版保留版本关系与历史结论，不能直接覆盖原证据。 |
| 差异处理 | 关联缺失、金额币种不符、重复、手续费或后续退回分开呈现；对账结论不无条件改写支付状态，核验动作走 K09。 |
| 依据／阻塞 | R08、R09、R11；A12；Q01、Q03、Q06、Q08、Q10。 |

### K09 提交差异核验结论

| 项目 | 需求级约定 |
| --- | --- |
| 输入含义 | 差异标识、原版本／当前结论、核验证据、处理原因、拟采取的业务动作；角色权限由 Q05／Q08 确定。 |
| 返回与边界 | 返回核验状态和审计关联。处理差异不等于批准新付款、退款或手改成功；涉及真实资金的新动作须有另行确认的业务契约。 |
| 并发与拒绝 | 防止多人基于旧结论互相覆盖；重复提交返回既有处理结果。无权、无证据或版本冲突拒绝并提示重新核验。 |
| 依据／阻塞 | R01、R08—R10；A07、A12；Q05—Q08、Q09。 |

## 四、定稿与联调边界

定稿前，银行对接方补 Q01／Q07 的实际协议与状态表，业务方确认 Q02—Q08，研发核对 Q09，相关角色确定 Q10。再填真实字段、类型、空值、路径、鉴权、错误码、签验及响应示例，并核对兼容性。

联调应从 A01—A12 中选择实际支持的能力执行，保留请求关联和脱敏证据。本次仅交需求级草案，未调用银行、未执行联调，也未验证签验、幂等、执行计划或吞吐。
